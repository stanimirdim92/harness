# The /ship command is renamed /release

**Context.** This Claude Code version has a built-in `/ship` skill. It
commits, pushes, opens a pull request and watches it. In the session's command
list, the built-in shows in place of the harness's `/ship`. The harness's
`/ship` is a read-only GO/NO-GO gate. The two do opposite things, so a user
who types `/ship` can push work that the gate never judged.

**Decision.** The harness command `/ship` is now `/release`. The owner chose
the name on 2026-11-25. `/release` does not collide with a built-in, and it
matches the command's own description, "Final release gate". The change is the
name and the file only:

- `claude/commands/ship.md` is now `claude/commands/release.md`.
- The Codex adapter `codex/skills/ship` is now `codex/skills/release`.
- Every live mention of the command and its path now says `/release`. That
  covers `claude/`, `codex/`, `tools/`, `README.md`, the CI comments and the
  maps under `docs/`.
- The workflow eval reads `commands/release.md`, and the `request` text of
  its gate cases says "Run /release".
- `docs/harness-map.html` is regenerated by `tools/checks/harness-map.py`.

The rename keeps the verdict vocabulary. The gate still prints `Ship Decision:
GO | NO-GO | SHIP BLOCKED`. The gate checks match those words by regex, and
the stored replay `expected` maps pin their results. A new word would make
every stored replay stale for no gain. The word "ship" stays where it is a
verb, such as "ship summary".

The rename also keeps these names:

- the stage keys `shipverdict`, `shipsteps` and `shipgate`, and the case ids
  such as `ship_open_blocker`. They are keys of stored data, not command names;
- the flag `check-ledger.py --ship`. It names the check that blocks release,
  and the tests call it by that name;
- the fixture files under each case and `fixture_manifest.json`, and the
  stored `tools/evals/workflow/replay/` files. They pin earlier results;
- the existing ADRs, audits, the observation log and other tickets' specs and
  plans. They are dated records, and the ADR index forbids editing them.
  Where they say `/ship`, read `/release`.

The approved HR-2 spec, plan and todo still say `/ship`. `docs/tasks/HR-2-open.md`
holds an open item for that.

**Rejected — *(/go).*** It is short, and it has no built-in. It reads as a
command to start work, though the gate only gives a verdict, and GO is already
a word in the verdict. A user who types `/go` might expect it to proceed.

**Rejected — *(/shipgate).*** It has no built-in either. It keeps the word
"ship" that caused the collision, and it is the name of an eval stage key
(`shipgate`). Two things would share one name.

**Rejected — *(keep /ship).*** The built-in hides the harness command in the
command list, and the owner cannot reach the gate from the list. A user who
types the name runs the built-in, which pushes. Keeping the name is the one
choice that leaves the defect in place.

**Revisit if** Claude Code adds a built-in `/release`. Then the same collision
returns, and the command needs another name.
