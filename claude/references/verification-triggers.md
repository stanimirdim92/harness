# Independent verification: when `/test` runs

`/build` always owns implementation-time verification. `/test` is the separate,
independent verifier. It runs the change the way an engineer would before
calling it done: frontend in a real browser, backend through real requests,
jobs and commands (ADR 0104). Tests passing is not the same as the change
working.

`/review` is the decision point. Require `/test` for every candidate that
changes production behavior: code, templates, styles, queries, migrations,
routes, jobs, commands, or configuration the running application reads. This
covers frontend and backend alike.

The candidate is **exempt** only when every changed file is one of these:

- documentation or comments with no runtime effect;
- tests, fixtures, or test configuration only;
- formatting only, with the project's formatter as the evidence;
- generated files only, regenerated by the project's own tooling;
- static content no code reads (a README image, a changelog).

A candidate that mixes an exempt file with a production change is not exempt.
These always require `/test`, even when a file looks exempt:

- `/build` could not complete a required check, or its evidence is incomplete,
  blocked, or not trustworthy;
- the change touches a path in the project's "Always a person" list
  (`always-person.py`, ADR 0096);
- the user explicitly asks for independent verification.

When uncertain whether a candidate is exempt, require `/test`.

This file is the single source of truth for the independent-verification gate.
Do not duplicate this list in `/review`, `/test`, or agent definitions.
