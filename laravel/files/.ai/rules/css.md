# Css

## Design tokens live in the lb-* @theme block; tailwind.config.js stays until migrated

resources/css/app.css runs Tailwind v4 with `@config "../../tailwind.config.js"` for the legacy v3 tokens. The Figma Light tokens are declared in a top-level `@theme` block with an `lb-` prefix (colours --color-lb-_, radii --radius-lb-_, shadows --shadow-lb-_, text styles --text-lb-_). Colour names and text-style names must differ (e.g. lb-ink for colour, lb-ui for size) because both become `text-*` utilities. Do not rename or delete legacy tokens in tailwind.config.js while any file uses them; do not change the shadcn HSL variables; do not hardcode Light hex values in CSS or components. Canonical values (current Figma contract, verified 2026-10-21 in Foundations 21355:13279 §06, Components 21363:15122 and the Light frames): brand #3E7888 (logo green, user decision 2026-10-22; was purple #6C49EB), ink #141B34 (Foundations says #002933; open decision, keep `lb-ink`), ink-secondary #586578, placeholder #768396, ALL product borders and dividers #DEDEDE (`--color-lb-border`, user decision 2026-10-22; `-card` and `-shell` are aliases of it; never reintroduce another border value), canvas #F3F4F8, success #2DBE64, warning #F5A623, error #FF4D4F, control radius 8px, container radius 16px (never 20px cards). Shadows: menus, popovers, tooltips and toasts 0 6 18 #002933/13% (`shadow-lb-popover`; `shadow-lb-dropdown` aliases it); modals and auth cards 0 12 30 #002933/18% (`shadow-lb-overlay`); inputs and selects no shadow; white and red (destructive) buttons, dropdown triggers and pagination buttons 0 4 12 #002933/12% (`shadow-lb-button`); brand buttons 0 6 16 rgb(37 72 82)/30% (`shadow-lb-button-brand`). Never put a button shadow on an input. `shadow-lb-control` is now only the favicon micro elevation (0 4 4 #000/4%); inputs, selects and search fields carry no shadow, and their focus is `border-lb-brand` + `ring-1 ring-lb-brand` (2px brand, no layout shift; error fields keep the error colour). Dropdown triggers and selects turn brand-coloured while open through `aria-expanded:border-lb-brand aria-expanded:ring-1 aria-expanded:ring-lb-brand` (built into `lbSecondary`); set `aria-expanded` on every trigger. Segmented controls: one bordered 8px container, square items, at most one internal divider, selected = `bg-lb-brand`. Modal and overlay cards use `shadow-lb-overlay`; modal status icons are `size-20` in the semantic colour (`text-lb-success` check, `text-lb-error` destructive, `text-lb-brand` informational). Button focus is `focus-visible:ring-2 ring-lb-brand ring-offset-2` (the `lbFocus` string in ui/buttons/button.tsx); raw `<button>`s repeat those classes plus `focus-visible:outline-none`. Never use the border tokens as fills: selected menu rows and slider tracks use `bg-lb-fill`; only 1px dividers may use `bg-lb-border*`. Use weight 700 for button labels.

## app.css is the single token source; tailwind.config.js is a grouped legacy layer (2026-10-15)

app.css has three `@theme` sections: A Light `lb-*` tokens (incl. `--spacing-lb-control*` heights and `--container-lb-modal-*` widths), B shell geometry (`--spacing-lb-header/rail/sidebar/aside/table-*`, `--breakpoint-xlp/xxl/xxxl`) and C the shadcn palette as `@theme inline`. Plugins load via `@plugin`, not the JS config. tailwind.config.js holds only legacy names grouped by role (`legacyColors`, `legacySizes`, `legacyAuthLayout`); never add a token there, and when a legacy colour shares a Light token's role reference `var(--color-lb-…)` instead of repeating the hex. Shell utilities are `h-lb-header`, `w-lb-rail`, `w-lb-sidebar`, `h-lb-table-filters`, `h-lb-table-ticker`, `h-lb-aside`; inside cn()/cva use the arbitrary form `h-[var(--spacing-lb-control-lg)]` so tailwind-merge still resolves conflicts. Details: docs/specs/DESIGN-SYSTEM-SPEC.md §3a.

## Use Manrope as the default font

Use Manrope as the default application font. Load weights 400, 500, 600, and 700 from `@fontsource/manrope`.
