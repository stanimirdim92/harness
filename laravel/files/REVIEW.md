## What Important means here

- A query that drops or widens integration scoping, or ignores
  `advertisers_hidden`, shows one customer another customer's data. Scoping is
  bespoke per query (`.ai/rules/models.md`), so check each changed query.
- A change that writes to, migrates or seeds the protected `leadbuster`
  database, or a test that escapes its per-checkout database.
- A migration without a real `down()`, or a schema change without the
  refreshed snapshot files (`database/schema/*`) committed together.
- A removed, hidden, disabled or relocated UI control, filter, menu item,
  modal or role-gated element that was not explicitly approved (redesign rule:
  Figma is incomplete, absence is not permission).
- A changed Inertia `useForm` payload, request parameter, route name or API
  response shape that an existing caller, signed feed link or export job
  still depends on.
- A Ticker list change that breaks cursor pagination (`cursorPaginate()`),
  creates gaps or duplicates between pages, or adds an N+1 query.
- A test edited to make failing behaviour pass ("a failing assertion is a
  question, not a defect").
- User-visible text that is hardcoded, missing an EN fallback, or missing
  from `lang/en` or `lang/de`.
- A new cross-module import that bypasses a published contract (deptrac
  layers, `.ai/skills/module-architecture/SKILL.md`).

## Do not report

- `public/build/**`, `vendor/**`, `node_modules/**`
- `composer.lock`, `yarn.lock`
- `database/schema/**` (generated by `bin/schema-refresh.sh`)
- `resources/js/components/icons/*.svg` (Figma exports; never review the paths)
- Pre-existing phpstan errors and deptrac violations outside the changed lines
- Whitespace-only changes made by the project formatters (pint, prettier)
- Behaviour that a DEC in the approved spec decides.

## Always check

- Behaviour claims need a `file:line` citation, never a guess from a name.
- Mark a defect the change did not introduce as pre-existing.
- Every changed query keeps its integration scoping and hidden-advertiser
  exclusion; cite the line that applies it.
- Every new route that takes an id has a test with the `bad route ids` dataset
  (`tests/Datasets/BadRouteIds.php`): each value answers a 4xx, never a 500.
- Every new request parameter has a FormRequest rule, and the signed feed path
  (`TickerExportController::export`, decrypted and unvalidated) cannot turn an
  odd value into a 500.
- Every new user-visible string in `resources/js/**` uses
  `trans('ns.key', 'EN fallback')`; on the backend, labels come from
  `trans('ns.key')` (its second argument is the replace array). Either way the
  key is in both `lang/en` and `lang/de`, and the DE value is translated.
- Frontend lists that mirror backend data come from backend props, not
  hardcoded copies (`.ai/rules/js.md`).
- Redesigned components use `lb-*` tokens only: no hardcoded hex colours,
  radii, shadows or font sizes.
- Each changed behaviour has a test that would fail without the change.
- A test's fixture matches the case its name describes (platform, role,
  status); no field is inherited from another case's fixture.
- A plan or spec `file:line` reference that the change moves is updated in the
  same commit.
- A migration that changes a column a queued job writes states the deploy order
  (pause Horizon, wait for workers, migrate) in the plan.
- When a fix changes a MUST condition, search the spec for every restatement of
  it.
- A command that reports what it wrote decides it from the statement's own
  result or a locked read, never from a later unlocked re-read.
- When a fix changes behaviour that a docblock, `#[Description]` or spec line
  states, that text is updated in the same commit.
- A branch that merges `main` reruns
  `vendor/bin/phpstan analyse --configuration=phpstan.ci.neon` and updates the
  `typeCoverage.*` totals in `phpstan-baseline.neon` in the same change.
